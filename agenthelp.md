# Social App Agent Handoff

This document is for any AI coding agent working on the Social repository. Read it before changing code.

## Project

Social is a local-first Expo/React Native social roleplay simulation. It includes:

- Fictional worlds with per-world persistence
- A ranked/chronological social feed
- Player and NPC posts, replies, likes, reposts, follows, and mentions
- Stories and story replies
- Main-character direct messages
- World events and player progression
- Notifications and unread state
- Activity history
- Achievements and XP
- Deterministic NPC simulation
- Optional on-device local language-model generation

Repository: `Techusic/Social`

## Stack and platform

- Expo SDK 57
- React Native 0.86
- React 19
- Expo Router
- TypeScript
- Zustand
- NativeWind
- Expo SQLite
- `llama.rn` for native on-device GGUF inference
- `expo-dev-client` for development builds

The app is currently being built for iOS. Expo Go can run the app, but it cannot load `llama.rn`; Expo Go uses deterministic fallback text. Real local AI requires an iOS development build.

## Core architecture

### Routing

Routes live under `app/`. Important screens:

- `app/index.tsx` — app hub and active-world picker
- `app/(tabs)/feed.tsx` — live feed and player posting entry point
- `app/(tabs)/chat.tsx` — main-character conversation list
- `app/new-chat.tsx` — starts a chat with an eligible main character
- `app/conversation.tsx` — direct-message conversation
- `app/story.tsx` — story viewer, creation, comments, and likes
- `app/(tabs)/notifications.tsx` — notification surface
- `app/activity-log.tsx` — persistent activity history
- `app/(tabs)/goals.tsx` — achievements, XP, and progression
- `app/customize-world.tsx` — world settings
- `app/event.tsx` — world-event choices

### Stores

- `stores/worldStore.ts` — worlds, active world, settings, world switching
- `stores/feedStore.ts` — posts, replies, relationships, memories, NPC simulation, feed persistence
- `stores/storyStore.ts` — stories, story comments, likes, viewed state
- `stores/messageStore.ts` — conversations, messages, unread messages, character replies
- `stores/eventStore.ts` — events and player progression
- `stores/activityLogStore.ts` — persistent activity records
- `stores/notificationStore.ts` — typed notifications and read state
- `stores/achievementStore.ts` — unlocked achievements and XP

### Persistence

Persistence uses Expo SQLite through:

- `db/worldPersistence.ts` — generic key/value storage and world hydrator registry
- `db/feedPersistence.ts` — typed feed snapshot storage

World-scoped keys use:

```text
world:<worldId>:<store>
```

Persisted domains include feed, stories, messages, events, activity logs, notifications, achievements, and world metadata.

When adding a new world-scoped store:

1. Load using the active world ID.
2. Persist using `worldStoreKey()`.
3. Register a hydrator with `registerWorldHydrator()`.
4. Test switching between at least two worlds.

## NPC behavior

NPC profiles are currently defined in `stores/feedStore.ts` in `npcProfiles`.

Current public actors include:

- Ginny Weasley
- Hermione Granger
- Quidditch Stats

`utils/npcEngine.ts` provides deterministic decisions and fallback text based on:

- Archetype
- Personality traits
- Relationship affinity
- Memories
- Target post tension
- Simulation tick

The root layout (`app/_layout.tsx`) advances the complete NPC cast immediately on app startup and every 30 seconds while the app is active. The Feed screen does not own the timer.

Each simulation cycle can cause NPCs to:

- Publish public posts
- Reply to player or NPC posts
- View target posts
- Like, repost, or follow player content
- Mention the player
- Send proactive messages
- Create stories
- Reply to player stories
- Change relationship affinity
- Trigger notifications, achievements, activity logs, and XP

Player posts are created through `app/create-post.tsx` and `feedStore.publishPost()`. They remain in the same feed and can be targeted by NPC simulation.

## Chat rules

Direct messages are intentionally limited to main characters. Eligibility is centralized in:

- `utils/profileLinks.ts`

Current chat-eligible IDs:

- `ginny`
- `hermione`

News accounts and NPC-only public actors can post and react publicly but must not appear in the chat picker or receive direct messages.

When adding a new main character, update the shared eligibility helper and the character source used by `new-chat.tsx` and `chat.tsx`.

## Local AI

`utils/localAi.ts` is the local model adapter.

Current behavior:

1. The first AI request downloads a Qwen 0.5B quantized GGUF model from Hugging Face.
2. The model is stored in the app document directory.
3. `llama.rn` initializes a native context.
4. Chat replies and simulated public post/reply text use the model.
5. Deterministic text is produced immediately so the app remains playable while the model loads.
6. If native inference, download, or initialization fails, the deterministic fallback remains active.

The adapter exposes a status:

- `fallback`
- `loading`
- `ready`
- `error`

Feed and conversation screens display this status. Errors are logged with `[local-ai]`.

The adapter shares one initialized context promise, but it does not yet expose download percentage or queue concurrent generations. Avoid starting many model requests in a new feature without adding a queue or rate limiter.

Do not bundle the GGUF model into Git. It is a large binary asset and is downloaded at runtime.

## Achievements and progression

Definitions live in `types/achievements.ts`.

The achievement store awards milestones for:

- NPC reply
- NPC mention
- NPC like
- NPC repost
- NPC follow
- NPC message
- NPC story reply
- Relationship change
- Social Gravity multi-reaction milestone

Unlocks are persisted per world and create:

- XP
- Activity-log entries
- Achievement notifications

`utils/progression.ts` calculates level and progress. The Goals screen combines event XP and achievement XP and displays both locked and unlocked achievements.

## Notifications and activity log

Notifications are player-facing and persisted per world. The Activity Log is also persistent and must not be cleared or truncated. Do not reintroduce a destructive clear action or a fixed history cap without explicit product approval.

Be careful when changing Zustand selectors. Do not return a newly-created array/object directly from a selector, for example:

```ts
useStore((state) => state.items.filter(...))
```

Select the stable collection first and derive filtered values with `useMemo`, or use a stable primitive selector. This project previously experienced maximum update-depth errors from unstable selectors.

- Preserve world scoping.
- Keep fallback behavior when native AI is unavailable.
- Do not commit secrets, API keys, model binaries, or user data.
- Run tests, TypeScript, and Expo lint after code changes.
- Use Expo-compatible package versions with `npx expo install`.
- Do not reset or discard unrelated worktree changes.
